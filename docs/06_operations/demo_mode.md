> **根拠ソース**: [src/app/layout.tsx](../../src/app/layout.tsx)、[src/app/page.tsx](../../src/app/page.tsx)、[.env.example](../../.env.example)

## 1. DEMOモードの有効化

> ID: DEMO-001

環境変数（ENV-003: `NEXT_PUBLIC_IS_DEMO`）を1行変更するだけで切り替えられます。

```env
# .env.local または デプロイ環境の環境変数
NEXT_PUBLIC_IS_DEMO=true   # DEMOモードON
NEXT_PUBLIC_IS_DEMO=false  # 本番モードOFF
```

- **[DEMO-002]** **注意**: `NEXT_PUBLIC_` プレフィックスの変数はビルド時に静的に埋め込まれます。変更後は `npm run build` の再実行が必要です（開発サーバーは自動反映）。

## 2. DEMOモード時の表示変化

> ID: DEMO-010

### 変更点 1: ブラウザタイトル（DEMO-011）

| モード | タイトル |
|-------|---------|
| DEMOモード | `ProfitLens - DEMO` |
| 本番モード | `ProfitLens` |

### 変更点 2: サイドバーロゴ横のバッジ（DEMO-012）

- **DEMOモード**: ロゴ「ProfitLens」の横に `DEMO` バッジ（オレンジ色）が表示される
- **本番モード**: バッジ表示なし

### 変更点 3: 警告バナー（メインエリア上部）（DEMO-013）

DEMOモード時のみ、以下のバナーが各タブ上部に表示されます:

```
⚠ これはデモ版です
データはSupabaseに保存されますが、テスト目的でのみ使用してください。
```

## 3. 機能制限について

> ID: DEMO-020

- **[DEMO-021]** **DEMOモードによる機能制限はありません。**

全てのCRUD操作（追加・編集・削除）、エクスポート・インポートが本番モードと同様に利用できます。
データは実際にSupabaseに保存されます。

## 4. デモデータの投入手順

> ID: DEMO-030

ステークホルダーへのデモンストレーション用にサンプルデータを準備するには、[demo-data.sql](../../demo-data.sql) を実行します。

1. Supabaseダッシュボードにログイン
2. 対象プロジェクトの **「SQL Editor」** を開く
3. `demo-data.sql` の内容を貼り付けて実行

**投入されるデータ概要**:

| ID | エンティティ | 件数 | 内容 |
|----|------------|------|------|
| DEMO-031 | 部署 | 3件 | 戦略コンサルティング部・ITコンサルティング部・人事コンサルティング部 |
| DEMO-032 | 役職 | 5件 | パートナー・マネージャー・シニアコンサルタント・コンサルタント・アナリスト |
| DEMO-033 | 要員 | 12人 | 各部署に4人ずつ配置 |
| DEMO-034 | プロジェクト | 6件 | 進行中3件・完了2件・予定1件 |
| DEMO-035 | アサイン | 65件以上 | 各月・各要員の工数配分 |

## 5. DEMO環境と本番環境のデータ分離

> ID: DEMO-040

- **[DEMO-041]** **推奨**: Supabaseプロジェクトを別々に作成し、接続先を環境変数で切り替えます（SEC-031 参照）。

```
DEMO環境 → Supabaseプロジェクト A
本番環境 → Supabaseプロジェクト B
```

> ※推測（要確認）: 同一Supabaseプロジェクトに DEMO データと本番データが混在している場合、データ管理が複雑になります。分離の実施状況は確認が必要です。
